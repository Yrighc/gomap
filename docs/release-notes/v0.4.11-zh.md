# GoMap v0.4.11

> 修复明文 HTTP 服务被误报为 TLS 的问题，保留非标准端口的 HTTPS 识别及超时前已确认的 TLS 信息。公开 SDK 结构和方法签名保持不变。

## 修复内容

### 明文 HTTP 不再被端口表误标为 TLS

此前，部分端口会因探针配置中的 `sslports` 进入 TLS 分支；即使 TLS 握手未确认，也可能直接返回“端口表服务名 + `/ssl`”，跳过后续明文探针。例如，8765 上的普通 HTTP 服务可能被输出为 `ultraseek-http/ssl`，导致调用方错误地使用 HTTPS 访问。

本版本调整为：

- TLS 握手未确认时继续执行明文探针，让 `GetRequest` 有机会取得实际 HTTP 响应。
- 不再根据端口表兜底生成 `/ssl` 标签。
- 不使用固定 TLS 端口白名单作为探测准入条件；非标准端口上的 HTTPS 仍可识别。
- 常见 Web 端口的快速识别、被动 banner 和特殊协议识别入口继续保留。

### 保留已经确认的 TLS 事实

- TLS 握手成功后立即记录传输层事实及该连接的证书信息，不依赖应用响应是否成功读取。
- 已确认 TLS、但没有匹配出应用协议时，返回 `unknown/ssl`，不使用端口表猜测产品名称。
- SDK 服务识别总预算到期时，仍保留此前已确认的 TLS 和证书信息；没有 TLS 证据时仍返回 `unknown`。

## 兼容性与注意事项

- 不新增或修改公开 SDK 结果字段、方法签名和事件类型；无需迁移 JSON 或数据库结构。
- 服务识别结果会变化：原先错误的 `ultraseek-http/ssl` 等结果可能变为实际识别出的 `http`；已确认 TLS 但应用未知的结果为 `unknown/ssl`。
- `unknown/ssl` 仅表示 TLS 已确认，不表示 HTTP 已确认。调用方不应仅凭 `/ssl` 后缀就把任意服务当作 HTTPS 网站。
- 非 TLS 的端口表猜测及既有 SDK 去除 `?` 的输出行为不在本次调整范围内。
- 不调整现有服务识别总超时预算；不包含主机发现、首页抓取或主动 Web 应用指纹能力变更。
- 开发环境新增 `.openidea` 忽略规则。

## 升级

```bash
go get github.com/yrighc/gomap@v0.4.11
```

CLI 用户可下载对应平台的发布产物。若上层缓存了旧的服务识别结果，需要重新探测后再使用新结果。

## 验证范围

- 本机 8765 回归覆盖明文 HTTP、HTTPS、未识别明文、未识别 TLS 和握手后静默 TLS，并检查 SDK 最终输出。
- 底层测试覆盖无 TLS 端口提示时的 HTTP/HTTPS 识别，以及握手成功后应用读取超时的证据保留。
- 收紧 HTTP 服务事件断言，拒绝把端口猜测名当作 HTTP 识别成功。
- 全量测试 848 项通过；`internal/tcpservices` 与 `pkg/assetprobe` 的 race 测试 70 项通过。
- 未访问用户现场目标，不将本机回归结果表述为现场复验。

发布工作流构建 Linux、macOS、Windows 的 amd64/arm64 六种产物并生成 SHA-256 校验和；跨平台构建不等于各平台实网验收。

## 发布范围
