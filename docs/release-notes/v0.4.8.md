# GoMap vNext
> assetprobe 主机存活校验默认启用、批量 CIDR 扫描增强、端口扫描管线拆分与 CLI 体验收口

---

## 概览

本版本是相对 `v0.4.7` 的一次 `assetprobe` 主题增强发布，重点围绕 **主机存活校验（HostDiscovery）**、**批量目标扫描入口扩展**、**TCP 扫描执行管线拆分**、以及 **CLI 实时日志与输出体验优化** 展开。

这一轮变化的核心不是单纯给 `port` 模式补一个 `-Pn` 开关，而是把 TCP 资产发现流程调整为更清晰的一条主路径：

`target normalize -> host discovery -> open-port discovery -> service fingerprint`

同时，批量扫描入口继续从“多 IP/域名列表”扩展为“IP/域名/CIDR 混合输入”，并把主机存活探测、批量预处理和日志输出收敛到统一语义上。

这意味着后续不管是通过 CLI 跑端口扫描，还是在 SDK 侧调用 `Scan` / `ScanTargets`，都能获得更一致的默认行为、更明确的跳过语义，以及更适合批量内网资产扫描的执行模型。

**对比基线**：`v0.4.7`

**更新规模**：19 commits | 25 files changed | +6,038 / -297 lines

---

## 重点内容

- **TCP 端口扫描默认接入 HostDiscovery**：先确认目标存在存活信号，再进入正式端口扫描
- **新增 `-Pn` 兼容语义**：可显式跳过 HostDiscovery，直接执行端口扫描
- **批量扫描支持 CIDR 输入**：`port` / `weak` 入口都支持在 `-ips` 中混合传入 IP、域名和 CIDR
- **扫描执行管线更清晰**：TCP 端口发现与服务识别拆分为两个阶段，便于控制成本与后续扩展
- **批量 HostDiscovery 并发化**：批量目标在进入端口扫描前可并发完成目标解析与存活校验
- **主机存活探测方式补齐**：覆盖 `icmp-echo`、`tcp-connect`、`tcp-syn`、`tcp-ack`、`arp`
- **CLI 体验继续收口**：端口扫描与弱口令扫描的帮助文本、错误提示、JSONL 输出和实时日志进一步统一

## 新功能

### HostDiscovery 核心能力落地

`assetprobe` 新增独立的主机存活探测能力，并接入 TCP 扫描主流程。当前支持：

- `icmp-echo`
- `tcp-connect`
- `tcp-syn`
- `tcp-ack`
- `arp`

默认情况下，TCP 扫描会先执行 HostDiscovery；如果没有获取到任何存活信号，该目标会被直接跳过，不再继续完整端口扫描。

### `-Pn` 与 SDK HostDiscovery 配置入口

- CLI `port` 模式新增 `-Pn`
- SDK 新增 `HostDiscoveryOptions`
接入位置：`assetprobe.Options`、`assetprobe.ScanRequest`、`assetprobe.ScanCommonOptions`

这意味着 CLI 与 SDK 现在都能以统一模型表达“是否跳过主机存活校验”。

### 批量目标支持 CIDR

`ScanTargets(...)` 与 CLI `-ips` 输入现在支持混合传入：

- 单个 IP
- 域名
- CIDR 网段

CIDR 会在批量入口被展开为具体 IP，并保持去重后的输入顺序返回结果。

### 扫描事件模型与实时日志基础

`assetprobe` 新增扫描事件回调与事件类型，当前覆盖：

- 主机存活命中
- 主机存活未命中
- 主机存活汇总
- 开放端口
- 服务命中

CLI 在 `-v` 场景下会把这些事件转成面向用户的实时日志输出。

## 变更

### TCP 扫描管线拆分

TCP 扫描不再把“发现开放端口”和“做服务识别”完全混在同一阶段中，而是调整为：

- 先做开放端口发现
- 再对命中的开放端口执行服务指纹识别

这让扫描开销控制、批量任务调度和 HostDiscovery 短路行为都更容易理解，也为后续进一步优化 fingerprint 成本提供了更稳定的结构。

### 批量预处理并发化

在 `ScanTargets(...)` 中，目标解析、CIDR 展开后的上下文准备，以及 HostDiscovery 现在会并发执行，再进入后续批量端口扫描阶段。

对于大批量但低存活率的内网网段，这一变化会明显降低“无效目标进入完整端口扫描”的成本。

### CLI 参数和输出体验统一

`port` / `weak` 命令行行为继续收口，主要包括：

- `-ips` 帮助文本明确支持 CIDR
- `port` 帮助文本补充默认 HostDiscovery 与 `-Pn` 语义
- `port` / `weak` 增加 `-jl` 单行 JSON 输出模式
- 参数校验错误文案更统一
- 空结果场景下的 CSV 输出补齐

### 批量模式日志更克制

批量扫描开启 `-v` 时，CLI 现在会优先输出：

- 主机存活汇总
- 实时开放端口日志
- 服务命中日志

并对逐目标 HostDiscovery 日志做了批量场景抑制，减少长列表扫描时的控制台噪音。

## 移除

### 旧的 HostDiscovery 细粒度 CLI 参数入口

原先规划中的 legacy HostDiscovery 命令行细粒度参数不再保留为当前 CLI 主接口。

当前对外推荐模型收敛为：

- 默认启用 HostDiscovery
- 需要直扫时显式使用 `-Pn`

这样可以避免把尚未稳定的内部探测细节过早暴露为 CLI 契约。

## 修复

### 主机存活默认配置修复

- 修复 HostDiscovery 默认配置装配问题
- 收敛默认模式、默认超时、默认重试次数与默认探测端口集合

### ICMP 存活探测超时语义修复

- 修复 `icmp-echo` 实现中超时与取消语义不清晰的问题
- 调整为基于 context 的命令执行方式，避免超时行为失真

### TCP 存活探测并发实现补强

- 新增并发探测常见端口的 `tcp-connect` 存活判断
- 收敛内部并发上限，避免单目标下探测成本不可控

### 批量 HostDiscovery 顺序与稳定性

- 修复批量存活探测并发测试中的超时问题
- 保持批量结果按输入顺序返回
- 在并发执行 HostDiscovery 时补齐汇总语义与测试覆盖

### CLI 边界行为补齐

- 空开放端口结果时也能写出 `port.csv` 行
- `-jl` 输出不再强制走 pretty JSON
- 移除后的旧 HostDiscovery flag 会明确报错，而不是静默忽略

## 说明与注意事项

- **这是一次 TCP 端口扫描默认行为变化版本**：`port` 模式现在默认先做 HostDiscovery，再决定是否进入完整端口扫描。
- **`-Pn` 语义与 Nmap 对齐，但成本不一定更低**：在低存活率网段中，跳过 HostDiscovery 可能会更慢，因为会把更多目标直接带进端口扫描。
- **HostDiscovery 当前主要面向 TCP 扫描主路径**：UDP 扫描不共享这套默认短路逻辑。
- **CLI 暂未开放所有 HostDiscovery 内部调优项**：当前推荐只感知“默认启用”与“使用 `-Pn` 跳过”这两个层级。
- **CIDR 展开会放大批量任务规模**：对大网段使用 `-ips 192.168.x.x/xx` 时，建议结合并发、速率与超时参数控制扫描成本。

## 升级与集成

### 作为 Go 依赖升级

如果你以库形式使用 `gomap`，建议：

```bash
go get github.com/yrighc/gomap@<next-tag>
go mod tidy
```

升级后建议重点检查：

- 是否依赖“TCP 扫描默认直接扫端口”的旧心智
- 是否需要在 SDK 侧显式设置 `HostDiscovery.Disabled`
- 是否需要消费新的扫描事件回调 `OnEvent`

### 作为 CLI 使用

- 若你希望延续旧的“直接扫端口”行为，可在 `port` 模式显式加 `-Pn`
- 若你在批量内网网段中只关心真正存活的目标，默认行为通常更合适
- 若你需要让输出更适合流式处理或日志采集，可使用 `-jl`

### 对平台集成方

- 批量目标现在可直接传入 CIDR，适合把网段展开逻辑从平台侧下沉到引擎侧
- 若平台要展示扫描过程，可接入 `OnEvent`
- 若平台只消费最终结果结构，现有 `ScanResult` / `BatchScanResult` 仍保持兼容
