# GoMap v0.4.9

> 为 `assetprobe` 增加显式的端口-only扫描模式，使调用方可以保留主机存活与开放端口发现，同时跳过 TCP 服务指纹识别。

---

## 概览

本版本相对 `v0.4.8` 增加一项默认行为兼容的 SDK 能力：调用方可通过 `DisableServiceFingerprint` 明确关闭 TCP 服务指纹阶段。

该选项适用于只需要开放端口事实、并由下游扫描引擎负责 Banner 与服务识别的集成场景。关闭服务指纹不会复用或改变 `MaxFingerprintPorts` 的既有含义。

**对比基线**：`v0.4.8`

**更新规模**：1 个功能提交，3 个文件变更

---

## 重点内容

- `ScanRequest` 与 `ScanCommonOptions` 新增 `DisableServiceFingerprint`。
- 单目标 `Scan` 与批量 `ScanTargets` 均支持端口-only模式。
- 端口-only模式继续执行主机存活探测和 TCP 开放端口发现。
- 端口-only模式不再建立服务指纹连接，服务、产品、版本和 Banner 保持为空。
- 未设置新选项时继续执行原有服务识别流程，现有调用方无需调整。

---

## 新功能

### 端口-only扫描

调用方可以在单目标或批量扫描请求中设置 `DisableServiceFingerprint=true`。扫描仍返回完整、去重且状态正确的开放端口结果，但跳过服务指纹阶段。

结果统计会明确反映：

- `OpenPorts` 保留实际开放端口数量；
- `FingerprintedOpenPorts` 为 `0`；
- 开放端口发现成功不会因跳过指纹阶段而转为失败。

---

## 兼容性说明

- 新选项默认值为 `false`，默认行为与 `v0.4.8` 一致。
- `MaxFingerprintPorts <= 0` 仍使用既有默认值，不作为关闭服务指纹的隐式开关。
- 本版本没有移除或重命名现有公共字段。
- `ScanRequest` 与 `ScanCommonOptions` 增加了导出字段；使用带字段名复合字面量的调用方源码兼容，使用位置式复合字面量的调用方需改为带字段名写法后升级。

---

## 升级与集成

Go module 调用方可升级到：

```text
github.com/yrighc/gomap v0.4.9
```

需要端口-only行为的调用方应显式设置 `DisableServiceFingerprint=true`；其他调用方无需修改。
